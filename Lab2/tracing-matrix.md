# Матриця трасування (DimPenShelf)

Матриця відображає двосторонні зв’язки «багато до багатьох» (Many-to-Many) між вимогами (EARS) і прецедентами (Use Case, UC-01 … UC-07). Кожна комірка містить посилання на пов’язані User Story ID та кожен Gherkin Scenario ID окремо (без скорочень).

Нумерація Use Case відповідає файлу `use-case-diagram.puml`:
- UC-01 — Перегляд каталогу книг
- UC-02 — Бронювання книги
- UC-03 — Оплата оренди книги (включно з розширенням `ExtPayRefund` «Повернення коштів при скасуванні»)
- UC-04 — Оформлення та відстеження доставки (розширює UC-02 за стереотипом `<<extend>>`)
- UC-05 — Отримання примірника (включає UC-03 за стереотипом `<<include>>`)
- UC-06 — Залишити відгук / оцінку
- UC-07 — Додавання книги та статистика читань (Автор)

## Легенда покриття
- ✓ — вимога пов’язана з прецедентом (Many-to-Many зв’язок).
- порожня комірка — немає безпосереднього зв’язку.
- **Uncovered** — вимога не має жодного пов’язаного прецедента (User Story / Gherkin / Use Case).

## Обґрунтування для непокритої вимоги
**EARS-11 (Uncovered):** «Система повинна дозволяти Читачу додавати книги у особистий список „Прочитані“ та список бажань». Ця вимога не має відповідної user story, Gherkin-сценаріїв і власного Use Case на діаграмі. Поточний обсяг лабораторної роботи зосереджений на каталозі, бронюванні, оплаті, доставці, отриманні примірника, відгуках та статистиці Автора; особистий список «Прочитані / бажання» виходить за рамки визначених прецедентів. Щоб покрити EARS-11, необхідно додати нову користувацьку історію, три Gherkin-сценарії та прецедент UC-08 «Керувати списками читання».

## Наскрізне трасування складних прецедентів («Історія → Сценарії → Вимоги»)

### 1. Прецедент UC-02 «Бронювання книги» (розширюється UC-04 «Оформлення та відстеження доставки»)
- **Історія:** `US-02` (Бронювання доступного примірника книги Читачем) та опціональне розширення `US-04` (Оформлення та відстеження доставки).
- **Сценарії та вимоги:**
  - `US-02-S1` (Успішне бронювання доступного примірника) → покриває вимоги `EARS-02` (право бронювати доступний примірник), `EARS-12` (обов'язкова попередня автентифікація) та `EARS-13` (фіксація дедлайну в UTC через інтерфейс Clock).
  - `US-02-S2` (Відмова при спробі бронювання примірника у стані РЕЗЕРВОВАНИЙ або ВИДАНО) → покриває `EARS-02` та `EARS-05`.
  - `US-02-S3` (Перегляд активних бронювань із термінами дії) → покриває `EARS-02` та `EARS-13`.
  - **Крайовий випадок 1 — Сплив часу життя бронювання (TTL):** `US-02-S4` (Автоматичне скасування простроченого бронювання через TTL) → покриває `EARS-09` (автоматичне повернення статусу ДОСТУПНИЙ та переведення бронювання у ПРОТЕРМОВАНИЙ) і `EARS-13` (єдине джерело часу Clock у UTC).
  - **Крайовий випадок 2 — Конкурентний доступ (Race Condition):** `US-02-S5` (Два Читачі одночасно намагаються забронювати останній доступний примірник) → покриває `EARS-02` та `EARS-05` (система атомарно резервує примірник лише за одним Читачем і блокує повторне бронювання для другого).

### 2. Прецедент UC-03 «Оплата оренди книги» (розширюється `ExtPayRefund`, включається у UC-05)
- **Історія:** `US-03` (Оплата бронювання та отримання квитанції).
- **Сценарії та вимоги:**
  - `US-03-S1` (Успішна оплата з внутрішньою системною дією авторизації платежу) → покриває `EARS-03`, `EARS-12`, `EARS-13` та `NFR-05` (безпека оплати).
  - `US-03-S2` (Відхилення транзакції під час авторизації оплати) → покриває `EARS-04` (відсутність квитанції та повідомлення про помилку).
  - `US-03-S3` (Повернення коштів при скасуванні замовлення — прецедент розширення `ExtPayRefund ..> UC3 : <<extend>>`) → покриває `EARS-04`.
  - **Крайовий випадок 3 — Оплата після спливу TTL бронювання:** `US-03-S4` (Спроба оплати простроченого за TTL бронювання) → покриває `EARS-09` та `EARS-13` (система відхиляє проведення оплати, оскільки TTL вичерпано, а примірник повертається у статус ДОСТУПНИЙ).
