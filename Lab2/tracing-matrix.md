# Матриця трасування (DimPenShelf)

Матриця відображає двосторонні зв’язки «багато до багатьох» (Many-to-Many) між вимогами (EARS) і прецедентами (Use Case, UC-01 … UC-08). Кожна комірка містить посилання на пов’язані User Story ID та кожен Gherkin Scenario ID окремо (без скорочень).

Нумерація Use Case відповідає файлу `use-case-diagram.puml`:
- UC-01 — Перегляд каталогу книг
- UC-02 — Бронювання книги
- UC-03 — Оплата оренди книги
- UC-04 — Оформлення доставки
- UC-05 — Отримання примірника
- UC-06 — Залишити відгук / оцінку
- UC-07 — Додавання книги
- UC-08 — Перегляд статистики читань

## Легенда покриття
- `✓` — вимога пов’язана з прецедентом (Many-to-Many зв’язок).
- порожня комірка — немає безпосереднього зв’язку.
- **Uncovered** — вимога не має жодного пов’язаного прецедента (User Story / Gherkin / Use Case).

## Рationale для непокритої вимоги
**EARS-11 (Uncovered):** «Система повинна дозволяти Читачу додавати книги у особистий список "Прочитані" та список бажань». Ця вимога не має відповідного user-story (немає US-07), немає Gherkin-сценаріїв і немає власного Use Case на діаграмі. Поточний обсяг Lab2 зосереджений на каталіку, бронюванні, оплаті, доставці, відгуках та статистиці Автора; особистий список «Прочитані / бажання» виходить за рамки визначених прецедентів. Щоб покрити EARS-11, потрібно додати: user story US-07, Gherkin-сценарії (US-07-S1…S3) та Use Case (наприклад, UC-09 «Керувати списком „Прочитані / бажання“»).
